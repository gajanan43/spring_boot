# ## **1️⃣ Encryption vs Decryption**

* **Encryption** = converting readable data → unreadable data
* **Decryption** = converting unreadable data → readable data

⚠ NOTE:
Encryption is used when you want **privacy of data**.

But **JWT does not encrypt data by default**, JWT is **signed, not encrypted**.

---

# ## **2️⃣ Digital Signature (Used in JWT)**

Digital Signature = Mathematical proof that:

* **Token is generated by the server**
* **Token is not modified on the way**

How it works:

1. Server generates token + secret key
2. Token gets signed using secret key
3. Client receives token
4. Client sends back token with each request
5. Server verifies signature using same secret key

If token is changed → **signature fails → token becomes invalid**

💡 Meaning:

> JWT = Tamper-proof authentication token

# ## **3️⃣ Why JWT? (Benefits)**

✔ No session required
✔ Stateless authentication
✔ Fast API calls
✔ Scales easily (microservices)
✔ Client stores token (not server)
✔ Works with mobile, browser, postman, microservices
✔ No need to hit DB on each request (optional)

# ## **4️⃣ What is JWT?**

JWT = **JSON Web Token**

Format:

```
Header.Payload.Signature
```

Example token:

```
eyJhbGci... (Header)
eyJzdWI... (Payload)
ks9dk_Ad... (Signature)
```

### Meaning:

* **Header** → algorithm + type
* **Payload** → user details, roles, expiry
* **Signature** → proves token validity

👉 Signature is generated using **secret key**

# ## **7️⃣ Generating JWT Token**

Use JWT library:

```java
String token = Jwts.builder()
        .setSubject(username)
        .claim("role", "USER")
        .setIssuedAt(new Date())
        .setExpiration(new Date(System.currentTimeMillis() + 1000 * 60 * 30)) // 30 min
        .signWith(SignatureAlgorithm.HS256, secretKey)
        .compact();
```

✔ `subject` = username
✔ `expiration` = token validity time
✔ Signed using secret key

# ## **8️⃣ Token Generated (Client stores it)**

Client must store token in:

* Browser LocalStorage
* Mobile app storage
* Postman header
* In-memory variable in single page app

Client must send token on each request:

```

```

# ## **9️⃣ Creating a JWT Filter**

Create a filter that:

* Reads **Authorization header**
* Extracts token
* Validates token
* Extracts username/roles
* Loads security context

Example filter:

```java
public class JwtFilter extends OncePerRequestFilter {
    @Override
    protected void doFilterInternal(HttpServletRequest request,
                                    HttpServletResponse response,
                                    FilterChain filterChain)
            throws ServletException, IOException {

        String authHeader = request.getHeader("Authorization");

        if(authHeader != null && authHeader.startsWith("Bearer ")) {
            String token = authHeader.substring(7);

            // validate token here
        }

        filterChain.doFilter(request, response);
    }
}
```

# ## **1️⃣1️⃣ Validating Token**

Token validation includes:

* Signature check
* Expiry check
* Username extraction

Example:

```java
String username = Jwts.parser()
        .setSigningKey(secretKey)
        .parseClaimsJws(token)
        .getBody()
        .getSubject();
```

# ## **1️⃣2️⃣ JWT Summary**

* JWT = Signed (not encrypted) token
* Stateless: no session stored in server
* Client stores token
* Token sent with every request
* Token validated using secret key
* Used in REST APIs, Microservices, Mobile Apps

⭐ Best for AUTHENTICATION without session

# 🌟 **JWT vs OAuth2 — Clear Difference**

| Feature              | JWT                     | OAuth2                          |
| -------------------- | ----------------------- | ------------------------------- |
| Use Case             | API authentication      | Social login / delegated access |
| Stateful / Stateless | Stateless               | Stateless                       |
| Who logs in          | Credentials from our DB | Google, GitHub, Facebook        |
| Token storage        | Client                  | Client                          |
| Security             | Very high               | Very high                       |
| Setup                | Custom                  | Almost auto                     |
| Best for             | REST APIs               | Social login systems            |

👉 JWT = You authenticate user yourself
👉 OAuth2 = You trust Google / GitHub to authenticate user
